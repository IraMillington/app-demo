Three iPhone apps, built with AI, running live

Ira builds and runs these apps with Claude Code and Codex: three iPhone apps, their servers, and the home server they run on. Each phone below runs the real app, the same source code that ships to Ira's iPhone, built for the browser. Only the data is invented, and the three phones talk to each other the way the real apps do.

Everything here is invented: the people, meals, recipes, photos, workouts and scores. Nothing you do on this page is sent anywhere. The demo is set on {{DEMO_DAY}}, the day its data was recorded.

How the three apps connect

Health is the hub. Recipes signs in with your Health account and sends meals to your Health diary; Claro sends the minutes you practice Spanish, which tick off a Health habit. Each app keeps its own data: Recipes has its own server and database, Claro keeps everything on the phone, and only these narrow links cross between them.

Recipes → Health

A Health account signs straight into Recipes: the Recipes server checks the password with Health and gets a link code back, so the diary is connected without a trip to Settings. Ingredients are matched to Health's own food database, recipes show nutrition per serving, and Save as a meal puts one serving into Health's saved meals, one tap from the diary. The Recipes server never stores the code or any nutrition data.

Claro → Health

Claro counts the minutes you actually practice (not minutes the app sat open) and sends them with a link code made from the habit in Health. A day that reaches the goal ticks the habit. Claro never holds Health's API key, and the code does only that one thing. Claro's optional answer translator also runs on the Health server, so the AI key stays off the phone.

Health · Expo / React Native · iPhone

Food, habits and training, with a camera that counts

Health is a food, habit, symptom and training tracker for two people in one household. It pulls steps, energy and sleep from Apple Health or Fitbit, and conditions picked at setup (lactose intolerance, IBS, high blood pressure and more) change what it tracks and which nutrients it weighs.

What makes it different

  • Up to four photos, one meal. A close-up and a wider shot sharpen the portion estimate. The model is told twice that the photos are one meal, so two angles never count as two servings.
  • The app reshapes itself around conditions. Lactose intolerance adds lactose in grams per meal against 6 g and 12 g limits, with a lactase check-off. Gut conditions add a 1–5 “how did it sit” rating for each meal and a monthly trigger analysis. Sam has none; Settings shows what each one would change.
  • An empty meal can mean something. “Didn’t eat this meal” records a real skipped meal, so a gap in the diary isn’t mistaken for a day you barely ate and felt fine.
  • A workout program that runs itself. Rotating workouts, a built-in logger with a rest timer and last time's weights, phases that change the effort target, and a progress chart for every lift.
  • A household leaderboard for steps, sleep, getting up and public habits.

The AI inside, and how the models were tested

  • Meal estimates: Gemini 3.8 Flash, picked Oct 20 after two tests. First, each candidate estimated 20 plates from Nutrition5k, a research set of real cafeteria meals whose calories are known, and was scored on calorie error, speed and failed calls. Second, the same leftover-pizza photo was run repeatedly to check that the answer holds still. Gemini 3.5 Flash Lite, the cheaper model in use until then, said a quarter, three quarters and seven eighths had been eaten on different runs (500 to 3,500 kcal). 3.8 Flash said three quarters every time, for about a cent more per estimate.
  • Fallback: Gemini 3.5 Flash Lite. In the same 20-plate test the previous fallback, Qwen3.8 Flash, was rate-limited on 9 of 14 calls and took about 54 seconds on the rest. Lite answered every call in about 5 seconds with about the same calorie error.
  • Monthly trigger analysis: Claude Sonnet 5.5. Chosen Sept 28 from published reasoning scores rather than a test of our own: within a few points of Opus 5.5 at half the price. It runs twelve times a year at 10 to 15 cents a run.
  • Models are a setting on the server, so they can be swapped without an app update. In this demo the AI answers are pre-written; everything the server does with them is real.

Recipes · Expo / React Native · iPhone

A cookbook shared with friends, linked to the food diary

Recipes is a social cookbook: everyone has a profile, adds friends and shares recipes with them, then saves or copies what friends share. It has its own FastAPI server and Postgres database beside Health's on the home server, with the same build, update and deploy setup.

What makes it different

  • Scale by what you have. “How much chicken do you have?” Type 1 lb instead of 1.5 and every amount follows, including the ones written inside the steps. US and metric measures sit side by side.
  • One visibility rule, checked in one place. A recipe is Only me, Friends or Everyone, and every read on the server goes through the same rule, so the feed, profiles and saves can't disagree about who sees what.
  • Save versus copy. Saving bookmarks the original and follows the owner's edits; copying gives you your own private version that remembers where it came from.
  • Nutrition from Health, not a second database. Ingredients are matched to Health's foods (its search lists foods you've logged before first), and a match is stored with the recipe, so a friend who copies it can log it too.

No AI, on purpose

  • Matching an ingredient is a search plus a unit conversion: a weight, or a cup or clove through the food's own portions. Anything it can't turn into grams (“salt, to taste”) is left for you to match instead of being guessed.

Claro · Expo / React Native · iPhone

Everyday Mexican Spanish for a returning beginner

Claro is a Spanish course built around real situations in Mexico: ordering at a fonda, calling the plumber, texting a friend. Units run from A1 to B2, with spaced reviews, graded readings, conversations and a hands-free “Just listen” mode for work. There is no account: progress lives on the phone. The one thing it sends is practice minutes, to a Health habit you link it to.

What makes it different

  • FSRS review timing. The same scheduler serious flashcard apps use. After 100 delayed reviews Claro fits one personal multiplier to how you actually remember.
  • “Say it and check.” Speech is recognized as Spanish (Mexico) on the phone and compared word by word with the sentence. It measures whether you were understood, not your accent, and nothing is recorded.
  • A writing checker that knows beginner slips. Soy 26 años, yo gusto, gracias para, a missing ¿ or accent. Slip categories feed a “What to work on” card, never your own text.
  • Practice anywhere. The 🎧🎤 pill says whether you can listen or speak right now. Turn speaking off and speaking prompts become writing prompts.
  • Mexican usage, explained. What ahorita really means, tú versus usted at work, and why ¿me pasas la sal? sounds natural.

The AI inside, and how the models were tested

  • Answer translator: Claude Haiku 5.5, picked Oct 28. The word-by-word check shows where a typed answer differs from the model sentence, but only a language model can say what the learner's own Spanish actually means. Ten models were given the same beginner answers, mistakes included, and compared on how well they read them. Haiku read them best, at about $0.00025 an answer. Gemini 3.1 Flash Lite, at the same price, is the fallback.
  • It only ever shows a translation and up to three notes. It never changes a rating or a score, it is sent only the prompt, your answer and the model answers, and it goes quiet offline. It is off in this demo.
  • Same pattern as Health: the AI call is made by the Health server, never the phone, so no API key ships in the app.
  • No AI where a rule does better. Review timing is the FSRS algorithm, the writing checker is hand-written rules for known slips, and “Say it and check” uses the phone's own Spanish (Mexico) speech recognizer.

How AI is used, in building and in the apps

Built with coding agents

The apps, their servers, the home server and this page are written with Claude Code and Codex. Each repository has an AGENTS.md runbook the agents work from (how to test, deploy and roll back, and what never to touch), and tests decide whether a change ships: about 940 server tests for Health, plus tests for Recipes and Claro. This page rebuilds itself when an app changes, and refuses to publish if a scripted step fails, a server errors or a real name turns up in the recording.

Models picked by testing them

Health's photo model was chosen by scoring candidates on 20 Nutrition5k plates with known calories, and by rerunning one photo to check the answer holds still. Claro's translator was chosen from ten models given the same beginner answers. The details are under each app. Models are server settings, so they change without an app update.

Guardrails around every call

Replies must match a JSON schema, and requests only go to providers that enforce it. A failure falls back to a second model, then reports an error instead of guessing. Photos are never stored, and the translator can't change a score. Where a rule does better than a model (review timing, writing slips, unit conversion), there is no model.

Tools for AI agents: PickleCourts

Ira is a co-developer of PickleCourts, a court-booking marketplace. On top of the read-only MCP server built by the other co-developer, Ira added venue search, account linking (OAuth), the booking tools and a plugin with a booking skill for Claude and ChatGPT. Booking needs a single-use confirmation token from a priced quote, so an assistant can't book twice or book something you didn't confirm. Search has been live in Claude's connector directory since Oct 12; the ChatGPT plugin with booking is in OpenAI's review.

Not built yet: a dedicated evaluation suite for these AI features. The model choices rest on the one-off tests above, and the plugin's reviewer test prompts (five that should trigger tools, three that shouldn't) are the start of one for booking.

What is real. All three phones run the apps' own source code, unmodified, exported for the web with Expo. Claro keeps its state on the device, so it runs here as on the phone (the optional answer translator, which needs the home server, is off); its demo learner was built by Claro's own scheduling and course code.

What is stood in. Health and Recipes talk to servers at home. For this page, those real servers ran against throwaway databases of invented people while a script tapped through these same builds, and the phones replay the recorded answers. The three phones share one recording, so a change in one shows up in the others. Your taps move the replay along, and settings you change are kept on the page; a change the script never made shows the closest recorded result instead. Reloading the page starts everything over. The AI photo estimates are canned answers that the server then processed for real. The browser has no camera roll, notifications or speech recognition, so those use small stand-ins.
